# Ai Software Factory launch review

Reviewed 2026-10-11. Product Hunt remains unpublished and unscheduled.

## Observed examples

| Launch | Verified result | Messaging pattern | Application |

| Lovable 2.0 | Product of the Day, 2025-04-25 | Specific app building outcome and collaboration | Lead with one reproducible example |

These are selected successful examples, not a causal study. Rankings do not establish conversion, revenue or why a launch succeeded. Existing audiences differ substantially.

## Draft copy

Name: Ai Software Factory

Tagline: Turn ideas into tested tools with verified release evidence

Description: An autonomous software factory for developers building CLIs, interfaces and MCP services. Follow research through tests, docs and release evidence. First shipped example: README Proof on npm. Start free with one project and one run request per 24 hours. Public requests need authorization; a request is not a completed build.

## Maker comment prepared for launch

I built Ai Software Factory because generating code is only one part of shipping a useful tool.

The first sweep produced README Proof: a local README checker with a CLI, browser UI, MCP tools and RVF evidence, published on npm. You can inspect the package and its release receipt today.

The platform brings project requests, verified workspace registration, tests, documentation and an operator release workflow together. The daily research loop is configured. I am still validating the live path from public registration through an authorized release, so I am not calling the public workspace unattended yet.

Free access includes one project and one run request every 24 hours. Public requests wait for authorization. Pro currently records interest only. Clean-room production requires separate observation and implementation environments plus independent review.

If you build developer tools, what would you put through the factory first: a CLI, an MCP service or a library integration?

## Gallery and distribution

Use a real factory screenshot first. Follow with the real README Proof inspection and registry views, explicitly presented as the shipped example. At least two gallery images are needed by Product Hunt. Target three images; recommended size 1270 by 760. A video should show actual actions and evidence; the existing package walkthrough is an example demo, not a complete factory run. Product Hunt accepts a full public YouTube URL for its video field; do not place an unsupported MP4 there.

Prepare three audience specific messages: developers interested in reproducibility, MCP builders interested in tool packaging, and existing ruvnet users interested in scheduled delivery. Ask for product feedback. Do not buy votes, request reciprocal votes, invent testimonials or send bulk unsolicited messages. No new promotional posts are sent as part of this draft review.

## Launch gate and measurement

Before scheduling, verify the saved identity, square thumbnail, at least two gallery images, maker comment and one live registration to authorized publication receipt. Ensure product identity no longer points to README Proof as the parent product; current legacy edit URL and breadcrumb still do.

Measure qualified visits, verified workspaces, authorized requests and completed releases. Internal pilot target: five external developers complete registration and three submit a valid bounded brief. This is a proposed readiness target, not observed traction. Do not optimize only for rank or votes. Do not use tracking parameters in the Product Hunt submitted primary URL.
